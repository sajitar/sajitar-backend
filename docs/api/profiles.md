# API `/profiles`

Query opcional **`lang`**: `en` (padrão), `pt` ou `es`. Omitida, vazia ou não suportada → inglês. Sem sessão e sem `Accept-Language`.

Autenticação **JWT HS256** (`Authorization: Bearer` com access token, claim `token_use=access`) emitida em [`/tokens`](tokens.md). Público: `POST /profiles`, `POST /profiles/password/recovery` e `POST /profiles/password/confirm` — um `Authorization` Basic ou Bearer inválido é ignorado. Demais rotas de `/profiles` exigem access Bearer válido, isto é, assinado **e** com registro ativo no Redis. Refresh JWT **não** vale no header. O token autentica o perfil. GET por id, details e lista **não** devolvem perfil que ainda tem checker `VERIFY_EMAIL`, salvo o caller com autoridade `MASTER` (404 sem corpo, igual a ausente; a lista omite no SQL). PUT/PATCH/DELETE não aplicam essa regra.

| Método | Caminho | Sucesso |
| --- | --- | --- |
| POST | `/profiles` | 200 + resumo (id, name, description; sem senha); cria internamente checker `VERIFY_EMAIL` e envia o código ao e-mail |
| POST | `/profiles/password` | 204; corpo `{ currentPassword, newPassword, signoutAllSessions? }`; só o perfil do Bearer; `signoutAllSessions: true` encerra todas as sessões |
| POST | `/profiles/password/recovery` | 204; corpo `{ email }`; cria ou gira `CHANGE_PASSWORD` e envia o código; e-mail desconhecido, `VERIFY_EMAIL` ou checker com mais de 12 horas também 204, sem e-mail |
| POST | `/profiles/password/confirm` | 204; corpo `{ email, code, newPassword }`; troca a senha e encerra todas as sessões daquele perfil |
| POST | `/profiles/email/recovery` | 204; Bearer; corpo vazio; cria ou gira `CHANGE_EMAIL`, zera o payload e envia o código ao e-mail vigente |
| POST | `/profiles/email/confirm` | 204; Bearer; corpo `{ code, newEmail }`; grava o payload e envia o código ao e-mail novo |
| POST | `/profiles/email/change` | 204; Bearer; corpo `{ code }`; grava o payload no perfil, encerra as sessões e apaga o checker |
| GET | `/profiles/{id}` | 200 + resumo |
| GET | `/profiles/{id}/details` | 200 + detalhes (sem senha) |
| PUT | `/profiles/{id}` | 200 + resumo; id só na URL; `password` e `email` extras são ignorados |
| PATCH | `/profiles/{id}` | 200 + resumo; campos omitidos permanecem; `"description": null` limpa a descrição; `password` e `email` extras são ignorados |
| DELETE | `/profiles/{id}` | 204; 404 se ausente (não é 204 idempotente) |
| GET | `/profiles` | 200 + página por cursor (`name`, `lastSeenName`, `lastSeenId`, `limit`, `reverse`; `precedingElements` / `followingElements`) |

Erros: **400** mapa campo→mensagens; **401** Bearer ausente ou inválido `{token:[…]}`, senha atual errada em `POST /profiles/password` `{credentials:[…]}`, recuperação com código divergente, checker ausente/vencido ou e-mail inexistente em `POST /profiles/password/confirm` `{code:[…]}` e `CHANGE_EMAIL` com checker ausente/vencido, payload no estágio errado ou código divergente `{code:[…]}`; **403** `{email:[…]}` nas etapas de `CHANGE_EMAIL` se o perfil ainda tem `VERIFY_EMAIL`; **409** e-mail já registrado (POST criar e confirmação/conclusão de `CHANGE_EMAIL`); **404** sem corpo; **429** `{credentials:[…]}` + `Retry-After` na troca de senha, na recuperação e na troca de e-mail; **503** store de sessões indisponível ou serviço de correio indisponível no POST criar, no pedido de recuperação e nas etapas de `CHANGE_EMAIL` que enviam correio. Detalhes no OpenAPI e na collection Postman.

O POST criar gera internamente um checker `VERIFY_EMAIL` e envia o código de verificação ao e-mail do perfil. Enquanto o checker existir, [`/tokens/signin`](tokens.md) responde **403** `{email:[…]}` se o `code` faltar, **400** se estiver mal formado e **401** `{code:[…]}` se divergir (o código vigente não muda); senha + código conferindo consomem o checker e abrem a sessão. [`POST /tokens/verification`](tokens.md) reenvia um código novo (429 só do limiter `CREDENTIALS`). [`/tokens/refresh`](tokens.md) responde **403** `{email:[…]}` se o checker ainda existir.

Trocar a senha (`POST /profiles/password`) com `"signoutAllSessions": true`, confirmar a recuperação (`POST /profiles/password/confirm`), concluir a troca de e-mail (`POST /profiles/email/change`) e excluir o perfil encerram **todas** as sessões daquele perfil em [`/tokens`](tokens.md), inclusive a corrente: o access deixa de valer na hora, sem esperar o `exp`. O encerramento precede a escrita, então Redis fora do ar responde **503** com o perfil intacto. Omitir `signoutAllSessions` ou enviar `false` na troca autenticada troca a senha e **mantém** as sessões. PUT e PATCH **não** alteram a senha nem o e-mail.

`POST /profiles/password/recovery` (público; corpo `{ email }`) cria o checker `CHANGE_PASSWORD` ou gira o código vigente (o id UUIDv7 permanece, então o prazo de 12 horas não reabre) e envia o HTML (código só no corpo). Sempre **204**: e-mail desconhecido, perfil com `VERIFY_EMAIL` ou checker com mais de 12 horas não enviam correio. `POST /profiles/password/confirm` (público; corpo `{ email, code, newPassword }`) confere o código, encerra as sessões e grava a senha nova. Código ausente ou mal formado → **400** `{code:[…]}`; divergente, checker ausente/vencido ou e-mail inexistente → **401** `{code:[…]}` (o código vigente não muda). O purge interno à meia-noite apaga o `CHANGE_PASSWORD` cujo UUIDv7 passou de `sajitar.profile.change-password-max-age-hours` (12), sem tocar o perfil nem as sessões.

A troca de e-mail corre em três POST autenticados, sem senha, sobre o perfil da sessão. `POST /profiles/email/recovery` (corpo vazio) cria o checker `CHANGE_EMAIL` com payload nulo, ou gira o código mantendo o id UUIDv7, limpa o payload se houver e envia os seis dígitos ao e-mail vigente — um novo recovery recomeça a troca para o `confirm` aceitar outro `newEmail`. Perfil com `VERIFY_EMAIL` → **403** `{email:[…]}`; checker vencido → **401** `{code:[…]}` sem girar. `POST /profiles/email/confirm` (`{ code, newEmail }`) exige payload nulo e código igual ao vigente: grava o `newEmail` no payload, gira e envia o código novo só para esse endereço. Código mal formado → **400** `{code}`; `newEmail` mal formado ou igual ao vigente → **400** `{newEmail}`; divergente, ausente, vencido ou payload já preenchido → **401** `{code}` sem girar; e-mail de outro perfil → **409** `{email}` sem consumir o código. `POST /profiles/email/change` (`{ code }`) só troca o e-mail com payload presente e código conferindo: encerra as sessões antes da escrita, grava o payload no perfil e apaga o checker. O código da primeira etapa, sozinho, não conclui a troca. **409** se outro perfil tiver registrado o payload nesse intervalo, com o checker preservado. O purge da meia-noite também apaga o `CHANGE_EMAIL` cujo UUIDv7 passou de `sajitar.profile.change-email-max-age-hours` (12), sem tocar o perfil nem as sessões.

A listagem **`GET /profiles`** pagina por cursor sobre nome e id. Quem não é `MASTER` não vê perfis com `VERIFY_EMAIL` (contagens de cursor no SQL). Exemplos de navegação também em `ProfileControllerIntegrationTest`.
